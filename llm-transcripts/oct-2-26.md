## Your restart-ssh-agent script

**Not yet. One word is missing, and there are two smaller snags.**

**1. It needs `export`. This is the big one.** Your line
`SSH_AUTH_SOCK="${DIR}/ssh-agent.sock"` sets the address inside the script's own
shell. But `ssh-add` is a separate program, and a separate program only sees a
variable that has been exported. So `ssh-add` doesn't know where the new
key-holder is, and you'd get "Could not open a connection to your authentication
agent."
- The sneaky part: if your desktop already exports a key-holder address, setting
  it again *does* reach `ssh-add`. So it might work in one terminal and fail in
  another. My shell has no address set at all, so from here it would fail.
- Fix: `export SSH_AUTH_SOCK="${DIR}/ssh-agent.sock"`

**2. "Restart" doesn't restart yet.** `ssh-agent -a` makes a little file called
a socket. That's the key-holder's mailbox. If the mailbox file is already there,
`ssh-agent` refuses with "Address already in use":
- If the old key-holder is still alive, the refusal is harmless. `ssh-add` hands
  the key to the old one.
- If the old one died but its mailbox file stayed behind, nothing is listening
  and `ssh-add` fails.

To really restart, it has to stop the old one (`pkill -f "ssh-agent -a
${DIR}/ssh-agent.sock"`) and delete the old mailbox (`rm -f
"${DIR}/ssh-agent.sock"`) before starting the new one.

**3. After a reboot, the folder is gone.** `tmp/shared-memory` lives in RAM, so
a reboot erases it. Then the mailbox has nowhere to go. The other scripts make
the folder before using it, and yours should too.
