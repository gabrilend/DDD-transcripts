You don't edit the pages on the server. You edit the words on your laptop, and

**Why.** The website is built. A program reads a few files on your laptop and

If you changed a page on the Linode by hand, the next push would write over it.

**Where the words live:**

| the page | where you change it |

**How it gets to the Linode:**

1. Change the file.
2. Commit it.
3. `git push`. The push hook builds the whole site into RAM, in
   `tmp/shared-memory/site/`. Then it copies it to the server, into the website
   folder `/var/www/abcd-games.net`.

If you want to look before you push, you have two choices:
- `./scripts/build-transcript-site` builds it, and you open
  `tmp/shared-memory/site/index.html` in Firefox.
- `./scripts/publish-the-site --dry-run` builds it and lists what *would* be
  sent, without sending anything.

To send without pushing, run `./scripts/publish-the-site` on its own.

`★ Insight
─────────────────────────────────────`
- **The copier never deletes.** It sends only files whose contents changed, and
  it never removes anything on the server. So if you rename or remove a page,
  the old one stays up until someone deletes it on the Linode on purpose. A
  broken build can't wipe the site, but old pages do pile up.
- **The story pages read the mirror, not the project.** The mirror is the line
  between private and public. So a story page only changes once the mirror has
  your change, and the push makes that happen first.
- **You need the key unlocked.** Sending uses the SSH key-holder, which forgets
  the key after eight hours. If it has forgotten, the build still works but the
  send fails. The push goes through anyway, with a loud warning.
